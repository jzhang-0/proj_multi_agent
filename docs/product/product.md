# 产品定义 — 总控台

一句话:**一台机器上多个 AI CLI 的群聊与指挥中心**,一个 TUI 程序,人从这一个界面里看到一切、指挥一切。

## 背景与现状

仓库里已有可用的最小总线(v0):`hub.py` 轮询 `bus/queue/` 把消息用 `tmux send-keys` 注入收件人终端,`msg` 命令供人和 AI 发言,`start.sh` 拉起 claude/codex/cursor/agy 四个成员。已实测跑通互相 @。总控台是在这条总线之上的产品化。

## 目标形态

一个命令启动的全屏 TUI(命令名 `amux`,原工作名 `console` 保留为别名),布局:

```
┌────────────┬─ 主画面 ─────────────────────────────┐
│≡ 群聊时间线│ 12:01 human→claude: 写fizzbuzz       │
│ 未读 3 条  │ 12:03 claude→codex: 请review         │
├────────────┤ 12:04 codex→human: 已通过            │
│○ claude    │  …选中成员时,这里换成它的终端画面    │
│◐ codex     │                                      │
├────────────┴──────────────────────────────────────┤
│ > @claude 修一下登录页的bug_                       │
└───────────────────────────────────────────────────┘
```

左边是**会话列表**(第一项群聊,后面每个成员一项,和聊天软件的联系人列表
一个意思),右边是**同一块主画面**——选中谁就显示谁。输入框在底部通栏。

- **会话列表**:群聊那项显示未读数;每个成员一张卡片:状态(空闲/工作中/排队 N 条/失联)、最后活动时间。
- **主画面 · 群聊时间线**:总线全部流量实时上屏,按成员着色,@ 高亮,可滚动回看历史。
- **主画面 · 成员画面**:实时镜像该成员的终端(看它正在干什么),不用切出去 attach;打开时把它的 tmux 窗口调成主画面大小,让它自己重排铺满;PgUp/PgDn 和滚轮翻的是它自己的回滚区。
- **输入框**:在群聊会话里是发言入口(`@名字` 自动补全,回车即发,`/` 前缀执行控制命令);在成员会话里**直接把这一行键入该成员的终端**——等于人在它自己的窗口里敲,想改回群聊就用 `@名字` 开头。直连动作照样进审计日志。
- **控制操作**(对选中成员):软打断(Esc/Ctrl-C)、终止、重启、全屏接管(attach)。

## 硬指标

| 指标 | 预算 |
|---|---|
| 消息入队 → 注入收件人终端 | P95 < 200ms |
| 消息 → 时间线上屏 | < 200ms |
| 成员详情画面刷新 | < 100ms(活跃窗格) |
| 键入回显 | 不掉帧(单帧 < 16ms) |

## 设计原则

1. **tmux 是唯一控制通道**。不逆向任何 CLI 的内部接口,成员对总控台零感知、零配合要求;任何新 CLI 只要能跑在终端里就能进群。
2. **总线契约冻结**。`./msg` 的命令行接口和消息 JSON 结构是成员依赖的公共契约,只能向后兼容地扩展(见架构决策 §3)。
3. **防环在传输层**。去重、限频、积压熔断由总线强制执行,不依赖模型自觉(借鉴 `reference/pi-extensions/src/talk/policy.ts` 的结论)。
4. **人永远优先**。人的消息不受限频约束,人的打断立即生效。

## 远期(本期不做,但架构要留口)

- IM 网关:手机群聊(飞书/Discord 等)双向接入同一条总线,`docs/goals/gateway.md` 占位,IM 平台选型是人的决策。
- 跨机器成员。

## 明确不做

- Web 界面、GUI 应用(本期只做 TUI)。
- 替代各 CLI 自己的会话管理/历史(总控台只管消息与控制,不管成员的对话内容存储)。
- 任何绕过各 CLI 权限机制的"自动点确认"(权限用各家的配置放行,见 roster)。
