# 视觉自验证:界面改完必须自己看画面

测试全绿只说明**逻辑**没错,不说明**画对了**。对齐错位、中文被截半个字、
选中态只有颜色没有形状、深色主题下灰字看不见——这些全都能测试通过。所以
CON 卷的每个 Goal 都要求:跑起来、截画面、逐条看、把截取物留档。

## 一、截画面

```bash
uv run python -m qa.visual --goal CON-003 --scene timeline --size 120x30 \
  --say "看看时间线长什么样" --keys Down
```

它做的事:临时 bus 根目录 → tmux 里起 `uv run console` → 等界面真的画出来 →
可选地发一条消息 / 发几个按键 → `capture-pane -p` 与 `capture-pane -p -e`
各存一份到 `tests/baseline/` → 关会话、删临时目录 → 核对机器上原有的 tmux
会话一个都没少。

参数:`--size 120x30`(宽屏)与 `--size 80x24`(最小可用尺寸)各来一次;
`--keys` 逗号分隔(如 `Down,Tab`);`--keep` 留着会话继续手动看。

手动版(等价,调试时用):

```bash
tmux new-session -d -s con -x 120 -y 30 "uv run console --bus-root /tmp/xxx"
sleep 4                                  # 一定要等,截早了是空屏
tmux capture-pane -p -e -t con           # -e 才有颜色
tmux send-keys -t con q                  # 收工
```

> **注意**:临时 bus 根目录只隔离队列,**不隔离 tmux**。在自验证的界面里
> 往真实成员名(claude/codex/…)发消息,消息会真的注入那个成员的终端。
> 要造流量就发给 `human`(只上屏不投递)或一个不存在的名字;真发了就
> `./msg <名字> 说明是界面自验证的测试消息` 去澄清一句。

## 二、看图判定清单

一条条对着截取物看,不确定就再截一张,**不允许凭上一张推断**。

### 对齐

- [ ] 三栏分隔线上下贯通,不错位、不断行。
- [ ] 每行右边框在同一列(中英文混排行尤其要看)。
- [ ] 边框不出现双线(自绘边框叠上组件自带边框会双)。
- [ ] 长内容按预期换行或截断,没有把布局顶宽、没有横向滚动条。

### 配色

- [ ] 前景/背景对比够,深色主题下次要文字仍可读。
- [ ] 选中态、焦点态一眼看得出是哪一个。
- [ ] 成员固定色彼此可区分,不靠猜。
- [ ] 拒收/失败这类"坏消息"的颜色与正常流量明显不同。

### 状态徽标

- [ ] `idle/working/stuck/dead/failed` 各有**形状**区分(●◐○✗ 之类),不只靠颜色——色盲和黑白终端都要能读。
- [ ] 徽标与名字之间不粘连,列宽固定不抖动。

### 中文宽度

- [ ] 中文按双宽计算,没有把边框挤歪。
- [ ] 中英文混排的行尾没有半个字被切断。
- [ ] 标点(,;「」)不落在行首行尾的错误位置。

### 尺寸

- [ ] `80x24` 最小尺寸下三个区域都还可用(详情栏按 CON-002 让位是正确行为)。
- [ ] 宽屏(≥ 120 列)下详情栏展开,时间线不被压扁。

### 退出安全

- [ ] `q` 与 Ctrl-C 各试一次,都干净退出。
- [ ] 退出后 `tmux ls`:成员会话一个不少,创建时间没变。

## 三、写证据

截取物落在 `tests/baseline/<goal-id小写>-<场景>-<宽x高>.txt`(带色版同名
`.ansi`)。CON 卷 Goal 的 `证据` 一行**必须引用实际截取物路径**,并写清在
画面上看到了什么(不是"界面正常"这种没有信息量的话)。

`tests/test_visual_evidence.py` 会检查:每个已完成的 CON Goal 都引用了
`tests/baseline/` 下**真实存在**的文件。

审美问题(首版配色、布局取舍)判断不了就标「需人工」,`./msg human` 请人
点头,不要自己拍板(见 [Goal 总索引](../goals/README.md)「视觉自验证」)。
